| 浏览和搜索 | `MainActivity`、`SearchActivity` 与 `CategoryCatalog`。两页共用 `FileActionActivity` 和 `DragSelectionController`，按路径维护选中状态。修改批量入口时同时验证目录页和搜索页。 |
| 存储权限 | `MainActivity` 使用系统「所有文件访问」设置页（API 30 起）或旧版运行时存储权限，返回后重查授权并刷新。`AndroidFolderAccess` 优先走普通目录，在内部共享存储的 Android/data、Android/obb 上探测兼容路径。打开后使用同一套文件列表和复制逻辑。两种路径都不可读时显示系统限制和本应用可读位置。见 [Android 目录兼容记录](docs/Android目录兼容记录.md)。 |

| 照片时间 | `MediaFacts` 读取 EXIF 原始拍摄时间、时区偏移和亚秒信息。`PhotoTimeSync` 写入并回读文件的最后修改时间。照片缺少有效拍摄时间时跳过。 |
| 设备互传 | `LanForeground` 在应用进程内持有发送任务和按 IPv4 接口绑定的接收监听。`LanNetwork` 通过 DNS-SD 发现设备，分别显示可达的无线和有线目标。`LanTransfer` 使用 TLS 指纹固定及按所选网络绑定的 TCP 套接字。有线路径请求 1 MiB TCP 发送和接收窗口，由内核按设备能力限制。仍沿用 `LanTree`、`LanFile` 的目录流、单遍读写和校验。1.0.24 至 1.1.2+27 可单层文件互传。 |
| BookDoctorC 模块迁移 | `BookMigration` 校验来件的 MIME、只读 URI 和文件名，`FileHandoff` 分块写入专用暂存目录。文件交给局域网传输后由应用任务释放暂存。接收方点 `.bdcm` 以只读授权打开 BookDoctorC 恢复。接口常量和文件归属见[开发说明](开发说明.md)。 |
| 时间戳原生层 | `app/src/native/c/file_times.c` 使用 Android NDK 的 `lstat` 和 `utimensat` 处理修改时间及访问时间。时间精度以目标文件系统回读为准，创建时间及 inode 状态变更时间由系统生成。 |

## 有线互传接线

- 两端打开 FileDoctorC，使用同一以太网，或通过系统已经建立的 USB 网络让两端获得互相可达的 IPv4 地址。接收端照常选择目录。两种网络同时可达时，同一设备可见两张卡片，带插头角标的是本机有线路由。
- Android 识别的以太网和 USB 网络通过 `ConnectivityManager` 分类。对没有 `Network` 对象的 USB 共享下游，尝试读取系统公开的 rndis、usb、ncm 接口地址并绑定源 IP。设备的 USB 模式和驱动决定是否出现可用网络。充电、MTP、ADB 和单纯接入线缆的状态本身不提供此互传协议所需的 IP 对端。
- 选择后的连接固定到卡片对应的接口。掉线后由当前任务反馈失败。替换接口、保存目录写入和可用空间仍按系统状态处理。真实有线速度取决于双方链路、TLS 和存储，网卡标称速率仅用于对照。

## 本机重建

工具链为 JDK 21、Gradle Wrapper 9.5.0、AGP 9.2.1、Android SDK Platform 37、Build Tools 37.0.0、NDK 28.2.13676358 和 CMake 3.22.1。源码的 `app/build.gradle` 和 Wrapper 配置是实际版本依据。

本机 SDK 位于 `D:\Codex\软件工程\tool\Android\sdk`。可用 JDK 21 位于 `D:\Codex\软件工程\.cache\zipdoctorc-1.0.18\jdk-21.0.13+9`，该目录只提供运行时。Windows 下优先使用 ASCII 的构建目录和 Gradle 缓存路径。若工作区已挂载为 `P:\`，可将 SDK 和 JDK 路径写成相应的 `P:\` 路径。

从当前源码目录运行下面的 PowerShell 命令。路径可按本机已验证的配置替换。

```powershell
& .\build-local.ps1 -Test `
    -Jdk 'P:\.cache\zipdoctorc-1.0.18\jdk-21.0.13+9' `
    -Sdk 'P:\tool\Android\sdk' `
    -GradleCache (Join-Path $env:TEMP 'FileDoctorC-gradle-cache') `
    -BuildDirectory (Join-Path $env:TEMP 'FileDoctorC-build-1.1.6+31')
```

脚本在独立目录构建 `fossRelease` 和 `fossDebug`、设备测试 APK，并运行 Lint 与 JVM 测试。正式未签名 APK 位于构建目录的 `app/build/outputs/apk/foss/release/app-foss-release-unsigned.apk`。工作区签名文件为 `D:\Codex\软件工程\密钥\release.p12`，别名为 `sevenzip-android`。使用 `sign-local.ps1` 的 `-UnsignedApk`、`-OutputApk`、`-Sdk`、`-KeyStore` 参数。口令通过进程内的 `ZIPDOCTORC_KEYSTORE_PASSWORD` 或 `-PasswordFile` 提供，按本地登记取用。

签名后确认包名、版本名和单调递增的版本码，核对 v2、v3 签名、证书摘要、16 KiB ZIP 对齐和最终文件 SHA-256。覆盖安装沿用原应用 ID、签名证书、私有目录和偏好设置。使用同证书的上一版在隔离设备测试升级、原存储权限及书签，随后回读设备实际安装的 APK 并核对摘要。

## 本地保留与恢复

当前项目位于 DoctorC 系列仓库的 `doctor-file` 子目录。历史稳定发行使用标签 `filedoctorc-v1.1.5+30`。源代码按工作区规则保留完整的本地检出，GitHub 远端的源文件和 APK 需下载核验后才能清理此前普通版本。Android 的版本码约束适用于恢复旧版。

本机继续复用 `.cache/zipdoctorc-1.0.18` 和 `.cache/zipdoctorc-1.0.23` 的 JDK 与虚拟设备数据。构建缓存使用 `P:\tool\Android\gradle-home`。见 [开发说明](开发说明.md)。
