## USB 直连与有线网络

- 小米 14 Ultra 与 17 Ultra 的现场状态是 14 Ultra 可从系统文件管理器浏览 17 Ultra 的 MTP 文件。这表示数据线已枚举且 14 Ultra 为 USB 主机，MTP 连接没有通用的应用对应用 IP 通道。
- Android 两端均需安装并打开本版。先保留系统「传输文件」模式，按系统提示授权 USB 设备和 FileDoctorC 配件。主机使用 USB 控制端点查询并启动 Android Open Accessory，对端会重新枚举。两端完成 FileDoctorC 自身握手之后，在原设备列表显示 USB 有线卡片。MTP 与 AOA 切换时系统文件管理器的原 MTP 连接会结束，重新插线可选回系统「传输文件」。
- `UsbCable` 管理 Android USB 主机权限、AOA 接口与 bulk 端点。`UsbTransfer` 管理握手、接收确认、取消和双向批次。在 USB 端点上传输目录数据流，复用 `LanTree`、`LanFile` 的校验、同名保护及落盘。每个物理连接一次只承载一批。应用聚合至 256 KiB，API 28 起主机使用异步直接缓冲读取并提交大块写入，配件驱动继续按自己的 16 KiB 接收上限拆分。握手与控制仍及时刷出。主机补齐短包边界，兼容保留 16 KiB 主机路径的旧 Android。
- `LanNetwork` 原有 USB 网络共享、以太网以及 Wi-Fi 路径继续参与同一列表，HTTPS/TLS 仍由 `LanTransfer` 处理。手机未成为 USB 主机或配件、OEM 禁用配件协议、系统授权被拒绝时，直连无法完成。两款小米的 USB 3.2 Gen 2 接口标称 10 Gbps。实际吞吐由协商结果、配件驱动、文件系统与 SHA-256 计算决定，面板显示实际 MiB/s。


- 有线与无线分别保留图标和选路。API 33 起额外在 Wi-Fi 网络发现设备，避免有线成为默认网络时漏掉无线目标。无线入口要求两端仍处于可互通的 Wi-Fi。
- USB 双端取消使用配件握手中的能力标志。新端接收取消时发控制帧，发送端终止负载，接收端清理未完成文件并保留已校验发布的文件。旧端不识别该帧时通过关闭 USB 传输会话取消。HTTPS 接收端取消中止当前会话和流，发送端回查取消状态。
- 方案比较参考 [Android AOA 配件驱动](https://android.googlesource.com/kernel/common/+/refs/heads/android15-6.6/drivers/usb/gadget/function/android_f_accessory.c)、[Android UsbRequest](https://developer.android.com/reference/android/hardware/usb/UsbRequest)、[LocalSend 协议](https://github.com/localsend/protocol#43-cancel)、[PhotoView](https://github.com/Baseflow/PhotoView) 及 [Android VideoView](https://developer.android.com/reference/android/widget/VideoView)。图片沿用项目已包含的 Glide，系统解码器直接用于视频，因此未引入 PhotoView、Media3 或第三方视频解码器。

## 媒体预览与硬件能力

- `MediaPreviewIntent` 将同类、去重的顺序写入应用私有缓存，大列表无需经 Binder 传全部路径。文件在显示时通过原 FileProvider 获取，重建时恢复当前页。缓存失效时仍可打开最初点击的文件。
- `MediaPreviewActivity` 使用 RecyclerView 吸附分页，放大图片时横移优先平移。相邻图片和视频按各自在当前列表或搜索结果的顺序切换，返回后继续浏览原界面。一屏只创建一个播放实例，后台释放，返回恢复当前进度与播放状态。
- HDR10、HDR10+、HLG 及 Dolby Vision 的输出由系统支持的编解码配置和显示器决定。可兼容的 Dolby Vision 片源可由 Media3 使用基础层播放。Dolby Digital、Digital Plus、TrueHD 及 Atmos 音轨依赖设备解码器和当前音频输出。音轨标记表示片源或选中的音轨，倍速时实际空间音频效果由系统输出路径决定。
- 参考 [Android HDR 播放能力](https://developer.android.com/media/grow/hdr-playback) 与 [Media3 格式支持](https://developer.android.com/media/media3/exoplayer/supported-formats)。不引入 FFmpeg、VLC 或杜比二进制模块。

## 本机重建

工具链为 JDK 21、Gradle Wrapper 9.5.0、AGP 9.2.1、Android SDK Platform 37、Build Tools 37.0.0、NDK 28.2.13676358 和 CMake 3.22.1。源码的 `app/build.gradle` 和 Wrapper 配置是实际版本依据。

本机 SDK 位于 `D:\Codex\软件工程\tool\Android\sdk`。可用 JDK 21 位于 `D:\Codex\软件工程\.cache\zipdoctorc-1.0.18\jdk-21.0.13+9`，该目录只提供运行时。Windows 下优先使用 ASCII 的构建目录和 Gradle 缓存路径。若工作区已挂载为 `P:\`，可将 SDK 和 JDK 路径写成相应的 `P:\` 路径。

从当前源码目录运行下面的 PowerShell 命令。路径可按本机已验证的配置替换。

```powershell
& .\build-local.ps1 -Test `
    -Jdk 'P:\.cache\zipdoctorc-1.0.18\jdk-21.0.13+9' `
    -Sdk 'P:\tool\Android\sdk' `
    -GradleCache (Join-Path $env:TEMP 'FileDoctorC-gradle-cache') `
    -BuildDirectory (Join-Path $env:TEMP 'FileDoctorC-build-1.2.1+35')
```

脚本在独立目录构建 `fossRelease` 和 `fossDebug`、设备测试 APK，并运行 Lint 与 JVM 测试。正式未签名 APK 位于构建目录的 `app/build/outputs/apk/foss/release/app-foss-release-unsigned.apk`。工作区签名文件为 `D:\Codex\软件工程\密钥\release.p12`，别名为 `sevenzip-android`。使用 `sign-local.ps1` 的 `-UnsignedApk`、`-OutputApk`、`-Sdk`、`-KeyStore` 参数。口令通过进程内的 `ZIPDOCTORC_KEYSTORE_PASSWORD` 或 `-PasswordFile` 提供，按本地登记取用。

自 1.2.0+34 的 ARM64 交付起，Gradle 和 `build-local.ps1` 均固定 `arm64-v8a`，可以在支持 ARM64 Android 应用的设备上覆盖安装同证书、同应用 ID 的以前版本。设备端测试使用 ARM64 Android 环境。

签名后确认包名、版本名和单调递增的版本码，核对 v2、v3 签名、证书摘要、16 KiB ZIP 对齐和最终文件 SHA-256。覆盖安装沿用原应用 ID、签名证书、私有目录和偏好设置。使用同证书的上一版在隔离设备测试升级、原存储权限及书签，随后回读设备实际安装的 APK 并核对摘要。
