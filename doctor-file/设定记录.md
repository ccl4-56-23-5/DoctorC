## 2026-11-20 · 1.1.5+30

- BookDoctorC 负责打包所选模块的源文件和记录，并在接收设备确认与恢复。FileDoctorC 从明确授权的只读 URI 导入一份 `.bdcm`，复用设备选择、接收路径确认、传输进度和数据校验。
- 成功、失败、取消或关闭设备选择后清理本应用暂存副本。接收设备在 FileDoctorC 点收到的 `.bdcm`，以只读权限交给 BookDoctorC。源设备和接收目录中的原件保留。

## 2026-11-20 · 1.1.4+29

- 选择接收设备后返回原页面。在浏览和搜索页使用同一份发送状态，可边浏览边传，并可从进度条旁取消发送。接收方确认保存路径后也显示批次进度。
- 百分比以本批已读写的数据字节计算，同时显示已处理项目数。全为空文件或空目录的批次按项目数推进。扫描和等待接收方确认时显示待定进度，成功以收端结果为准。完成、失败或取消结果可手动关闭。
- 传输由应用进程持有，Activity 切换或销毁时继续。已确认的接收任务会保留监听直至任务结束。系统回收应用进程、强行停止或网络断开会中断传输。

## 2026-11-20 · 1.1.3+28

- ZipDoctorC 改名为 FileDoctorC，沿用同一软件的版本序列、应用 ID 和签名，覆盖安装时保留既有数据与授权。
- 底栏采用酷安评论区气泡液态玻璃。主页和搜索结果的操作托盘匹配操作组材质，主页独立搜索圆匹配按钮气泡。保留原有图标、布局、拖动触区、前景清晰度及非线性的过渡和回弹。可用 GPU 执行增艳、高斯模糊、折射和表面合成，其他设备走兼容材质。
- 局域网传输支持同时选中文件和文件夹，保留目录层级和空目录。删除发送、接收流程的 256 项限制。接收方仍需确认实际保存目录，已存在的同名项按原有编号语义避让。
- 发送端逐文件单遍读取并计算 SHA-256，接收端校验后发布，保留文件修改时间与访问时间。兼容旧版单层文件协议，文件夹或超过旧版上限的批次需要两端升级。

## 至 1.1.2+27 的有效设定

- 低于 API 30 使用系统运行时权限，API 30 起由系统「所有文件访问」统一授权。Android 文件夹在「文件 → 我的手机」中打开，受限目录取决于系统支持的访问路径。1.1.2+27 移除了独立 Android 快捷入口。
- 压缩删除源文件默认关闭。开启后仅删除完整读取并校验成功、复核后仍匹配的源文件。
- 宽屏压缩首页最近记录采用双列。搜索页与文件列表共用多选、拖选、全选和文件操作。书签随批量重命名更新。
- 批量重命名日期来源包含修改时间、EXIF 拍摄时间、EXIF 优先。同步照片时间只更新文件最后修改时间，保留照片内容。
- 局域网设备使用 DNS-SD 发现，通过 TLS 证书指纹识别，前台页面可以收到接收请求。保存目录由接收端每批确认。真机平板、折叠屏及 PC 类型显示仍待设备核验。
