# FileDoctorC

## 目标

在 Android 上从同一套文件浏览和搜索界面完成压缩、解压、重命名、查看本机图片与视频、打开 APK 安装器和设备间文件互传。文件管理各处保持一致的视觉层次和交互反馈。

## 约束

- C1. 首页底栏、独立搜索圆和搜索结果操作栏采用 RikkaHub/Haze 2.1.0 的固定强效果，去掉中部模糊，保留清晰边缘折射、独立前景和连续变形。边缘高光保持窄幅且有方向，选中项使用明暗填色区分，避免出现环形白边。应用无需强度设置。
- C2. 无线和有线目标共用设备列表、接收确认、进度与落盘流程。识别到双方可达的有线连接时显示单独的设备卡片，用右上角线缆图标区分。两台 Android 手机直接通过 USB 线相连时，支持主机与配件模式在同条连接上双向传输。两条路径可达时分别显示插头与 Wi-Fi 目标，由发送者点击选择。双方都可取消进行中的批次。
- C3. 短按批量重命名规则立即打开已有规则，并将焦点和可视位置移到最直接决定产出名称的字段或选项。
- C4. 继续使用当前应用 ID、签名和数据格式，以便设备可覆盖更新并保留原有设置、规则和书签。

- C5. 图片和视频默认在应用内查看，按当前文件列表或搜索结果的同类顺序左右切换。图片放大后保留平移。视频可调倍速并使用设备支持的 HDR 和杜比解码能力。APK 短按打开系统安装确认。优先复用设备解码能力，控制安装体积。

- C6. 所有交付 APK 仅含 `arm64-v8a`。本地普通版本和 DoctorC 上的 FileDoctorC Release 均只保留最新 ARM64 版，移除旧发布页时保留 Git 标签与提交。维护封包如包含 APK，只纳入最新 ARM64 包。

沿用上级软件工程工作区规则。以源码根目录的 维护文档.md 为重建入口，以 设定记录.md 接续已确认的历史要求。
