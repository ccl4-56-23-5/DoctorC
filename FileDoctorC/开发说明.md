# FileDoctorC 1.1.5+30 维护入口

## 变更位置

- `DockGeometry` 按实际窗口和安全区布局，尺寸计算的基准宽度上限为 420 dp，操作托盘上限为 544 dp。压缩首页达到 840 dp 时，最近压缩包切成双列，内容区域最大 1040 dp。底栏和独立搜索圆复用独立背景采样，分别应用酷安评论区的操作组和按钮气泡参数。文字与图标独立绘制。
- `NativePopups` 通过 `MotionFrames.sourceReveal` 将回收末段的透明度交还真实来源按钮。`MorphSurface` 先收掉弹层阴影，再开始交接。
- `SearchActivity` 是独立的全屏搜索页面。从目录进入时，关键词或类型默认筛选当前目录。来源筛选查找已识别的公开目录，可与文件名和类型组合。全局文件搜索复用 `CategoryCatalog`，文件夹和来源查找复用可取消的目录遍历。打开结果沿用 `MainActivity` 的文件动作。
- 搜索结果使用 `DragSelectionController` 处理长按拖选，以文件路径保持选中状态。搜索和浏览共用 `FileActionActivity` 的压缩表单、目录选择器、文件操作服务和批量重命名入口。任务完成后搜索按原条件更新结果。
- 批量重命名的 `DATE` 规则通过 `dateSource` 保存日期来源，旧方案默认读取最后修改时间。预览在后台从原照片读取 `DateTimeOriginal` 和可用的 `OffsetTimeOriginal`。严格 EXIF 模式将缺失拍摄时间列为行错误，混合模式使用文件修改时间作为回退。执行使用已确认的预览目标。 [AndroidX ExifInterface](https://developer.android.com/reference/androidx/exifinterface/media/ExifInterface)
- 照片时间同步从浏览和搜索的多选菜单进入，由 `NativeFileService` 后台运行 `PhotoTimeSync`。复用 `MediaFacts` 对拍摄时间、时区和亚秒字段的解析。确认文件身份后只写文件的最后修改时间，回读允许存储按秒截断，已更新的路径请求媒体扫描。取消后保留已完成项。
- `LanForeground` 持有发送协程、接收监听和双向进度状态，由浏览与搜索共同观察。空闲监听随可见页面启停，已确认接收任务持有监听至结束。Android DNS-SD 通告型号、品牌、形态、地址和 TLS 指纹。发送端校验发现时收到的完整指纹，接收端逐批确认目录。文件夹和超过旧版容量的批次要求两端至少为 1.1.3+28，兼容的旧版本仍可使用原单层文件协议。 [Android DNS-SD](https://developer.android.com/develop/connectivity/wifi/use-nsd)
- `LanBatchProgress` 按整批数据字节计算百分比，另显示已处理项目数。零字节批次按项目数推进。进度刷新按批次限频。浏览页和搜索页分别保留发送与接收结果，直至手动关闭或同方向下一批任务。发送正在等待接收端校验时最多显示 99%。
- 新协议的准备请求只提交总数、总字节和最多八个根项目预览。接收者确认目标目录后，发送端在一个 TLS 上传请求中依次写入文件、进入文件夹和结束文件夹记录。每个文件的 32 字节 SHA-256 尾部在单遍读取时计算，接收端验证后从临时文件发布。短读、校验失败和中断会清理当前临时文件及仍为空的未完成目录，保留已发布项目。通过 NDK 的 `lstat` 和 `utimensat` 恢复并回读纳秒精度的 mtime 和 atime，存储精度不足时在批次结果提示。 [Android Bionic 文件属性接口](https://android.googlesource.com/platform/bionic/+/master/libc/include/sys/stat.h)
- `MainActivity.showSettings` 和 `showBookmarks` 负责左上角三点菜单。书签保存在 `native_ui` 的 `directory_bookmarks` 字符串集合。批量重命名会更新目录和子目录的引用。外部移动或删除后的失效路径可从列表移除。

## BookDoctorC 模块迁移

- 发送端发出 `local.sevenzip.android.action.SEND_BOOKDOCTOR_MIGRATION`，目标包为 `local.sevenzip.android`，类型为 `application/vnd.bookdoctorc.migration+zip`。同一 `content://` URI 放在 `EXTRA_STREAM` 和单条 `ClipData` 中，附只读授权。
- `BookMigration` 从 `OpenableColumns.DISPLAY_NAME` 校验 `.bdcm` 文件名。大小已知时检查空间和实际读取长度。文件分块复制到应用私有暂存目录，再使用原有设备选择。选择期间由页面持有副本，开始传输后交给 `LanForeground` 释放。进程异常退出遗留的副本在下次暂存前清理。
- 浏览与搜索共用的文件打开入口把收到的 `.bdcm` 用 `ACTION_VIEW` 交给 `local.bookdoctorc`，MIME 和只读授权与发送约定一致。模块、源文件和记录的内容校验及恢复由 BookDoctorC 执行。

## 构建、签名和验证

- 使用 JDK 21、Gradle Wrapper 9.5.0、AGP 9.2.1 内置 Kotlin、Android SDK Platform 37、Build Tools 37.0.0、NDK 28.2.13676358 和 CMake 3.22.1。最低 API 24，目标 API 35。正式包版本名为 `1.1.5+30`，版本码为 `31`，应用 ID 为 `local.sevenzip.android`。
- `build-local.ps1 -Test` 在独立构建目录生成 FOSS 发布包、调试和设备测试包，并运行 Lint 和 JVM 测试。可通过 `-Jdk`、`-Sdk`、`-GradleCache` 指定本机环境。Windows 上构建目录和传给 `-GradleCache` 的路径使用 ASCII 字符，避免 Gradle 测试进程找不到 Worker 类。现有缓存可通过一个 ASCII 路径的目录联接访问。
- `sign-local.ps1` 接收 `-UnsignedApk`、`-OutputApk`、`-Sdk`、`-KeyStore`。签名别名为 `sevenzip-android`。由本地密钥登记设置进程环境变量 `ZIPDOCTORC_KEYSTORE_PASSWORD`，或提供 `-PasswordFile`。Windows 原生工具使用无中文字符的构建与临时 APK 路径。
- 正式包位于工作区 `output\FileDoctorC\1.1.5+30`。截至 1.0.6 的 Git 历史在 `history\source-through-1.0.6.bundle`。重建、签名和交接流程见 [维护文档](维护文档.md)。
