# 液态玻璃设计

以真实背景上的可读控件为目标。保留项目既有风格，优先扩展已有材质、模糊库及动画基础设施；先检查平台能力、许可和最低版本，再决定是否增加着色器。用户当次要求优先，勿把某个项目的外观或参数变成所有应用的硬性要求。

## 先确定材质与层级

明确需要玻璃的控件、背景来源、可读前景及状态变化。先处理密集文字、缩略图、明暗背景和深色主题，再追求折射强度。

- **背景**：取自不包含玻璃自身及其前景的独立内容层。禁止捕获自身祖先形成递归、重影或反馈。
- **材质**：背景先轻度高斯模糊，再进入折射/色散/着色，最后裁出真实轮廓。提高遮蔽度意味着减少背景透出，不是降低整个控件的 alpha。
- **前景**：文字和图标最后独立绘制。不给包含它们的整个 View/容器施加模糊、透镜变形或非等比缩放。
- **高光与边缘**：细而连续，服从同一个轮廓。不要在模糊最终成品时把轮廓一起揉散。

若已有全宽渐隐模糊顶层，优先让上面的按钮继承该合成背景，再叠加局部着色；直接重新采样原始列表可能在模糊顶层中挖出清晰的“洞”。独立玻璃底栏则可有自己的背景透镜。不要为每一个按钮重复捕获和模糊整屏。

Android 实现时读取 [references/android.md](references/android.md)。其他平台先核实其原生背景模糊/合成能力，再采用相同的背景—材质—前景分离原则。

## 调整可读性与几何

用实际密集内容逐项调整，避免同时大幅改变多种参数：

- 背景字过于抢眼：先增加中性色遮蔽，再加少量背景模糊。大模糊会擦掉透镜边缘的折射证据；保持可辨的光学轮廓。
- 浅/深色单独调底色、遮蔽与细边，不对整层统一反色。保持图标的既有视觉重量。
- 胶囊、正圆、选择透镜使用同一套实际尺寸推导轮廓；正圆宽高相同，图标保持原始长宽比。按可用宽度、字体缩放与安全区重新计算布局。
- 布局和输入区域由控件拥有，光学材质只负责画面。长按透镜外凸不应意外拉伸文字、覆盖其他操作或扩大成整块透明触摸拦截层。
- 滚动顶栏若采用“页面大标题→折叠标题”模式，控制大/小标题衔接和全宽模糊的连续渐入。只有该模式适用时才采用；不擅自给其他应用强加顶栏结构。

## 参照应用的悬浮底栏

参照指定应用时，先确认平台、版本和启用的材质模式。优先在实际应用中记录首页静止、滚动和拖动释放，区分容器、选区和独立操作。记录安全区内的高度、左右留白、间距、选中前景、阴影与背景透出。将这些关系映射到目标应用自己的标签数量、色板和动作；保留完整触区及辅助功能选中状态。静态截图只能说明构图和当时的材质。

- 用户只要求借鉴玻璃材质时，锁定现有底栏尺寸、间距、图标素材和配色。分别核对几何与前景，再调整背景、边缘、选区和光学动效。
- 托盘提供低对比边缘和稳定底色。选区用轻度折射与高光分层，避免为选区再加一层厚投影。拖动时只让透镜跟手，图标和文字保持原位和原尺寸。
- 松手时允许选区沿运动轴轻微回弹，位置与按压形变分开收敛。反向、取消和连续操作从当时的可见位置接续。回弹幅度受托盘边界和邻近按钮约束。
- 评估成熟库与项目现有渲染路径的匹配程度。已经有独立背景采样、兼容材质和手势状态的项目，可以直接调整对应层，避免为了相似效果更换 UI 框架。

## 连续非线性动效

复用项目同一套曲线与驱动器。把按钮、托盘选区及弹出菜单视为连续形状变化，避免先隐藏后硬切。

- 从触发控件的实际可见屏幕边界变形到菜单/面板目标边界，同时插值圆角；正文保持目标排版，以轮廓裁剪逐步显露，文字不随轮廓缩放。
- 进入和退出均连续。中途关闭、再次触发或取消时，从当前进度接续，取消旧驱动器的回调，避免跳回初始状态。
- 来源控件临时隐藏时，记住原 alpha。接近回收终点时先卸掉弹层投影，再把透明度连续交还真实按钮，避免窗口移除当帧同时出现旧投影和原按钮。完成、取消、销毁和异常退出都恢复原值。菜单触摸边界随实际可见轮廓处理。
- 长按/拖动只增强适量的放大、边缘折射与外凸；释放、越界、多指、CANCEL 和切页均回到一致的静止状态。
- 遵守系统动画缩放/关闭设置。静止时不另建无用途的逐帧计时器；背景改变时使用平台显示列表或已有模糊更新机制。

## 真实验证与交付

验证应针对变化及实际风险，不把所有项目机械地扩展成整套大工程。

1. 在真实渲染路径检查浅/深色、密集文字/缩略图、滚动前后、窄屏/大字号，以及相关长按/拖动/取消状态。区分模拟器、实体设备、自动验证和用户验收。
2. 用细条纹确认玻璃主体确实柔化背景；用较宽彩色条纹确认边缘发生坐标重映射，而非仅叠白色/灰色。重新测量模糊变化后的信号，不能为了过测试随意降低阈值。
3. 核对前景宽高、位置、缩放及图标像素仍完整。截图取样必须等待平台窗口启动动画完成；可在有时限内等待实际像素稳定，真正缺失仍应失败。
4. 录制真实打开、收回、打断与取消动效。逐帧检查回收末段及窗口移除后相邻帧，核对轮廓外有没有突然变深、双重投影或单帧空白。正常速度验证观感，慢速复现定位责任层。不要用生成帧代替设备录屏，也不以录屏推断真实帧率或功耗。
5. 保留可回退的兼容材质，明确未测平台。性能检查关注背景捕获次数、重复模糊、临时对象、CPU 像素读回及生命周期释放；仅在有证据时扩大优化范围。

输出改动、所用参数、验证结果和实际边界。保持业务数据、既有菜单和文件操作语义；整理设计不自动授权重写业务、增加确认流程或发布到新仓库。
